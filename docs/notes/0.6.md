## Набор линтеров и почему

Стандартный набор (errcheck, govet, staticcheck, unused, ineffassign) плюс:

- **правила проекта машиной, а не ревью:** `gochecknoglobals` (sentinel-ошибки
  и `go:embed` линтер разрешает сам), `gochecknoinits`, `forbidigo` (`os.Exit`
  только в `cmd/*/main.go`; `fmt.Print*` запрещён — логи через slog),
  `revive` (doc-комментарии у экспортируемого);
- **корректность:** `errorlint`, `exhaustive` (switch по `apperr.Kind`),
  `bodyclose`, `noctx`, `rowserrcheck`, `sqlclosecheck`, `nilerr`, `unparam`;
- **безопасность:** `gosec`;
- **`nolintlint` с `require-explanation`:** каждый `//nolint` с причиной.
  Сейчас в коде ни одного `//nolint`.

Исключения в конфиге с причинами: `forbidigo` для `os.Exit` в `cmd/*/main.go`;
в `_test.go` — `gosec`, `noctx`, `gochecknoglobals`, `unparam`. Для
`context-as-argument` разрешён `*testing.T` перед ctx (конвенция хелперов).

## Что нашёл линтер в существующем коде

21 находка, все исправлены (коммит `phase0(0.6): fix findings…`):
отсутствующие doc-комментарии в коде 0.1 (httpserver, App, Env, cmd/api),
`net.Listen` без ctx → `net.ListenConfig` (Listen теперь уважает отмену),
сравнение `ErrAbortHandler` через `==` → `errors.Is`, switch без
`default`, неиспользуемый результат `loader.secret`, мелочи staticcheck.

Проверка `go mod tidy` в CI сразу нашла расхождение: testcontainers был
помечен `// indirect`, хотя импортируется integration-тестами напрямую.
Исправлено в этом же этапе.

## ADR

0001–0005 — архитектурные решения из ТЗ; 0006–0010 — решения этой фазы:
формат ошибок, драйвер БД, мигратор, порядок middleware, конфигурация и
секреты. Про соответствие везде — «спроектировано по контролям X» со
ссылками на конкретные пункты (HIPAA 45 CFR §164.3xx, GDPR ст., ISO/IEC
27001:2022 Annex A, SOC 2 CC). Для законодательства РК номера статей не
указаны: их нужно сверить с юристом, а не выдумывать.

## Что не проверено

- **Workflow ни разу не запускался на GitHub:** ветку не пушили (по
  договорённости). Проверено локально: каждый шаг выполнен теми же
  командами и версиями инструментов (golangci-lint v2.14.0 и govulncheck
  v1.8.0, собранные Go 1.27). Не проверены сами экшены на раннере и то,
  что на `ubuntu-24.04` доступен Go 1.27 через setup-go.

## Что можно было сделать иначе

- Закрепить Docker-образ Postgres по digest, а не по тегу `18.6-alpine`.
- Dependabot/Renovate для обновления SHA экшенов и зависимостей Go.
- Отдельный job с `-count=20` для пакетов с сокетами и конкурентностью —
  сейчас это делается локально при изменениях.
