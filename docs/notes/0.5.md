# 0.5 — Postgres

## Что сделано

| Что | Где |
|---|---|
| Настройки БД, тип `Secret`, конфиг мигратора | `internal/config` |
| tenant ID и tenant-контекст | `internal/shared/tenant` |
| Пул pgx/v5, `WithinTx` с `SET LOCAL`, требование TLS | `internal/platform/postgres` |
| Свой мигратор на `go:embed` | `internal/platform/postgres/migrate.go`, `migrations/`, `cmd/migrate` |
| Readiness с проверкой БД (500ms) | `internal/platform/health` |
| Роли БД, docker-compose, Makefile | `deploy/postgres/initdb/10-roles.sh`, `docker-compose.yml`, `Makefile` |
| Integration-тесты (testcontainers) | `tests/integration` (tag `integration`) |

Новые переменные: `NEURODENT_DB_DSN` (обязательна, секрет),
`NEURODENT_DB_MAX_CONNS` (10, [1, 100]), `NEURODENT_DB_CONNECT_TIMEOUT` (5s),
`NEURODENT_DB_STATEMENT_TIMEOUT` (5s, инвариант `< HANDLER_TIMEOUT`),
`NEURODENT_DB_MAX_CONN_LIFETIME` (30m); для мигратора — `NEURODENT_ENV`,
`NEURODENT_MIGRATE_DSN`. Почему такие значения — в комментариях к дефолтам.

## Модель изоляции

```
роль neurodent_owner  — владелец схемы, только cmd/migrate (DDL)
роль neurodent_app    — API: только DML по грантам, NOBYPASSRLS, не владелец
таблица               — ENABLE + FORCE ROW LEVEL SECURITY
политика              — tenant_id = NULLIF(current_setting('app.tenant_id', true), '')::uuid
транзакция            — WithinTx: SELECT set_config('app.tenant_id', $id, true)
```

- **`set_config(..., true)` = `SET LOCAL`.** Значение живёт до конца
  транзакции. С `false` оно осталось бы на соединении, и следующий запрос из
  пула — другого tenant'а или без tenant'а — увидел бы чужие строки. Мутация
  это подтверждает.
- **`NULLIF(..., '')`.** Ловушка Postgres: после первого `SET LOCAL` на
  соединении параметр в следующих транзакциях равен `''`, а не `NULL`.
  `''::uuid` — ошибка, и запрос без tenant'а падал бы вместо «ноль строк».
  Тест проверяет это явно на пуле из одного соединения.
- **FORCE.** Прикладная роль не владелец, для неё хватило бы ENABLE. FORCE
  закрывает владельца: миграции и ручные сессии под ним тоже не видят строк
  без tenant'а.
- **Пул наружу не отдаётся.** Весь доступ идёт через `WithinTx`, так что запрос
  мимо транзакции с tenant'ом невозможен.
- **Будущие политики — `AS RESTRICTIVE`.** Permissive-политики объединяются
  через OR и могут ослабить изоляцию (комментарий в миграции).

## Ключевые решения

**Свой мигратор (≈150 строк), а не goose/golang-migrate/atlas.** Нужно
немного: embed, версии подряд, транзакция на миграцию, advisory lock,
контрольные суммы. Своё даёт ровно это без зависимости с её транзитивными
пакетами и CVE. Плюс то, чего нет «из коробки»: `lock_timeout` внутри
миграции (ALTER TABLE, ждущий ACCESS EXCLUSIVE, иначе ставит в очередь весь
трафик к таблице) и отказ, если БД новее бинарника. Только вперёд: откат
медданных — новая миграция, не down-скрипт. Ограничение: `CREATE INDEX
CONCURRENTLY` нельзя в транзакции; понадобится директива «без транзакции».

**`Secret` — структура с `fmt.Formatter`.** Первая версия (`String` +
`GoString`) протекала: для `%d` fmt не вызывает `String()` и печатает поля
структуры через reflection. Это поймал `TestSecret_NeverPrinted`, который
перебирает глаголы. `Format` перехватывает все. Структура, а не `type Secret
string`: `string(secret)` в обход `Reveal` не компилируется.

**Ошибка разбора DSN не оборачивается** (`ErrInvalidDSN` без `%w`).
Ошибки соединения оборачиваются: pgconn вырезает пароль, а хост и
пользователь нужны оператору. Тесты проверяют отсутствие пароля в тексте
ошибок для обоих случаев.

**TLS вне dev обязателен** (`RequireTLS`): отклоняется DSN, допускающий
plaintext, включая `sslmode=prefer`, у которого plaintext — запасной вариант.
Рекомендуется `verify-full`; принудительно не требую: у `verify-ca` в pgx
тоже `InsecureSkipVerify` с собственной проверкой, и отличить надёжно сложно.

**Таймауты на стороне БД:** `statement_timeout` из конфига (< handler timeout),
`idle_in_transaction_session_timeout` 30s (брошенная транзакция держит
блокировки), `application_name` для `pg_stat_activity`.

**`WithinTx` откатывает при панике без recover.** `defer` выполняется при
раскрутке стека; паника идёт дальше, до Recover-middleware. Откат — на
`context.WithoutCancel(ctx)` с таймаутом: контекст запроса мог быть отменён,
а откатить нужно.

**`shared/tenant` отдельно от будущего `shared/auth`**: tenant нужен и там,
где пользователя нет (фоновые задачи, консьюмеры). `ID` — структура,
создаётся только через `Parse` (канонический UUID).

**Пароли dev-БД не в репозитории.** `make db-env` генерирует `.env` (в
.gitignore) со случайными паролями; compose без них не стартует
(`${VAR:?}`). Порт слушает только 127.0.0.1.

**Postgres 18.6.** 19 пока в beta (`19beta4`). В PG18 есть встроенный
`uuidv7()` — первичный ключ технической таблицы. С 18 образ хранит данные в
`/var/lib/postgresql/18/docker`, том монтируется на `/var/lib/postgresql`.

**Integration-тесты — один `TestPostgres` с подтестами**, а не `TestMain` с
глобальным контейнером: окружение передаётся замыканием, глобального
состояния нет. У каждого подтеста свои случайные tenant'ы. Скрипт ролей тот
же, что в compose; версия образа сверяется тестом с `docker-compose.yml`.

## Мутации

| Мутация | Упавший тест |
|---|---|
| `set_config(..., false)` вместо `SET LOCAL` | `no_tenant_context_sees_zero_rows_even_on_a_reused_connection` (видна 1 строка) |
| Без `FORCE ROW LEVEL SECURITY` | `FORCE_RLS_restricts_the_owner_too` (владелец видит 6 строк) |
| Без `NULLIF` в политике | `no_tenant_context_sees_zero_rows_even_on_a_reused_connection` (`''::uuid`) |
| Прикладной роли `BYPASSRLS` | `app_role_cannot_bypass_RLS`, `tenant_sees_only_its_own_rows`, `cross-tenant_insert…`, `no_tenant…`, `WithinTx…` |
| `Secret` без `Format` (исходная версия) | `TestSecret_NeverPrinted` (DSN в выводе `%d`) |

## Проверено вручную

`make db-env && make db-up && make migrate` (дважды — второй no-op), API на
этой БД: `/readyz` 200 → `docker compose stop` → `/readyz` 503 с warn-логом,
`/healthz` 200, SIGTERM — чистая остановка, пароль в логе не встречается.

## На что смотреть при ревью

- `tx.go`: флаг `committed` и откат в `defer` — единственный путь коммита.
- `0001_platform_rls_probe.sql`: комментарии к FORCE, NULLIF и RESTRICTIVE.
- `10-roles.sh`: атрибуты ролей и `REVOKE ALL ON SCHEMA public FROM PUBLIC`.
- `migrate.go`: порядок lock → table → verify → apply; `lock_timeout`.

## Что можно было сделать иначе / обсудить

- **Readiness и общая БД.** При падении БД все реплики станут unready, и
  балансировщик ответит своим 503 вместо нашего. Это требование ТЗ, но
  частый аргумент — readiness не должен проверять общие зависимости.
  Компромисс: проверять только «пул может выдать соединение» и терпеть
  короткие сбои (failureThreshold).
- Роли с фиксированными именами. Для ротации паролей без простоя лучше
  NOLOGIN-группа `neurodent_app` и LOGIN-пользователи `neurodent_app_v1/v2`
  в ней; гранты — группе.
- Гранты явные в каждой миграции (а не `ALTER DEFAULT PRIVILEGES`):
  каждое право видно в ревью миграции. Цена — легко забыть грант; ловится
  первым integration-тестом модуля.
