# 0.4 — middleware

## Что сделано

- `internal/transport/http/middleware`: `RequestID`, `AccessLog`,
  `SecurityHeaders`, `Recover`, `BodyLimit`, `Timeout`, `Chain`.
- `internal/app/router.go`: `registerRoutes` (все маршруты в одном месте),
  `newRouter` (цепочка с обоснованием порядка), `routeProblems` (404/405
  роутера в формате RFC 9457).
- `internal/platform/logger`: `WithAttrs(ctx, …)` — атрибуты из контекста
  попадают в каждую запись `*Context`-методов. Так `request_id` проходит во
  все логи запроса.
- `internal/config`: `NEURODENT_HANDLER_TIMEOUT` (10s, [1s, 1m]),
  инвариант `HANDLER < WRITE`.

## Порядок цепочки

```
RequestID → AccessLog → SecurityHeaders → Recover → BodyLimit → Timeout → routeProblems(mux)
```

| Слой | Почему здесь |
|---|---|
| RequestID | первым: id нужен логам паник, access-логу и телам ошибок |
| AccessLog | снаружи Recover/Timeout: видит итоговый статус (500, 503) и полную длительность |
| SecurityHeaders | снаружи всех, кто сам пишет ответ (Recover, BodyLimit, Timeout) |
| Recover | снаружи Timeout: Timeout переносит панику из goroutine хендлера, ловит её Recover |
| BodyLimit | до Timeout: 413 по Content-Length без запуска goroutine |
| Timeout | ближе всех к хендлеру: бюджет тратится только на хендлер |

Порядок проверяется не «списком», а его наблюдаемыми следствиями
(`TestRouter_ErrorResponsesAreUniform`): ошибка из любого слоя (404, 405,
413 по Content-Length и по chunked-телу, 503, 500, 500 после частичной
записи) даёт problem-ответ с `request_id` = `X-Request-ID`, со всеми
security-заголовками и строкой access-лога с итоговым статусом.

## Ключевые решения

**Свой Timeout вместо `http.TimeoutHandler`.** Stdlib отдаёт фиксированное
тело `text/plain` без `request_id`. Механика та же: хендлер пишет в буфер в
своей goroutine, клиент получает либо ответ хендлера, либо 503, но не смесь.
Тонкие места:
- паника в goroutine хендлера передаётся в goroutine запроса вместе с
  исходным стеком (`panicError`), иначе Recover залогировал бы стек места
  re-panic;
- передача паники и установка `timedOut` идут под одним mutex: паника либо
  доходит до Recover, либо (после таймаута) логируется — но не теряется молча;
- после таймаута запись хендлера возвращает `http.ErrHandlerTimeout`;
- если клиент ушёл сам (родительский ctx отменён), ответ не пишется;
- **следствие буферизации:** нет `Flush`. Стриминг (ответы AI-ассистента)
  придётся монтировать мимо этого middleware.

**Recover паникует сам в двух случаях** — это штатный механизм net/http, а не
нарушение запрета на panic: `http.ErrAbortHandler` обрывает соединение без
записи в лог. (1) хендлер сам паникует с `ErrAbortHandler` — пропускаем;
(2) ответ уже начат — дописать 500 нельзя, а обрезанный 200 клиент принял
бы за успех. С Timeout внутри случай (2) практически не наступает: ответ
буферизован. Есть тест на реальном соединении.

**Шаблон маршрута в access-логе берётся у роутера до хендлера** (`mux.Handler(r)`),
а не из `r.Pattern`: middleware ниже передают дальше копию запроса
(`r.WithContext`), и `Pattern`, выставленный `ServeMux`, на наш экземпляр не
попадает. Для `CONNECT` ServeMux возвращает сырой путь вместо шаблона — пишем
`unmatched`. В лог не идут путь, query, IP, User-Agent (тест проверяет, что
ИИН из пути и query в логе нет).

**Входящий X-Request-ID** принимается при длине 8–64 и алфавите
`[A-Za-z0-9._-]`. Невалидный заменяется своим (`crypto/rand.Text()`, 26
символов). Алфавит исключает инъекцию в логи и заголовки ответа.

**404/405 в формате RFC 9457.** ServeMux пишет их как `text/plain`.
`routeProblems` при отсутствии маршрута прогоняет хендлер ServeMux на
«пустом» writer, узнаёт статус и `Allow`, и пишет problem-ответ. Редирект
на очищенный путь сохраняется (есть тест).

**BodyLimit: 1 МиБ, константа, а не переменная окружения.** Файлы идут в
object storage по pre-signed URL; JSON-тела — килобайты. Лишний параметр —
лишний способ ошибиться; эндпоинт сужает лимит в `DecodeJSON`. Для 413
новой категории в apperr не понадобилось (см. 0.3).

**HSTS** — 2 года, `includeSubDomains`, без `preload` (из preload-списка
выходят месяцами — отдельное решение). В dev выключен: HSTS на localhost
ломает другие локальные проекты.

## Найденный flaky-тест

Первый `make test` (с `-shuffle=on`) упал: кейс «413 на chunked-теле»
получил 503. Все кейсы роутера шли с таймаутом хендлера 20ms, а чтение
1 МиБ под `-race` при параллельных тестах иногда дольше. Короткий таймаут
теперь только у кейса, где он должен сработать. После исправления —
50 перемешанных прогонов зелёные. Хороший пример, зачем `-count=N`: один
прогон этот тест проходил.

## Мутации

| Мутация | Упавший тест |
|---|---|
| SecurityHeaders перенесён внутрь (после Timeout) | `TestRouter_ErrorResponsesAreUniform/{body_limit_by_Content-Length,handler_timeout,panic,panic_after_partial_write}` |
| AccessLog перенесён внутрь Recover | `TestRouter_ErrorResponsesAreUniform/{panic,panic_after_partial_write}` (в логе 200 вместо 500) |
| RequestID принимает любой входящий id | `TestRequestID/{newline…,non-ascii…,quote…,space…,too_long…,too_short…}` |
| Timeout не выставляет `timedOut` | `TestTimeout_SlowHandlerGets503AndLateWritesFail`, `TestTimeout_PanicAfterTimeoutIsLogged` |

## Покрытие

middleware 99.4% (непокрыта ветка гонки «паника ровно в момент таймаута»),
logger 100%, config 99%. `app.New/Run` покрываются в 0.5 интеграционным
тестом (после появления БД).

## На что смотреть при ревью

- `timeout.go`: `forwardPanic` и ветка `ctx.Done()` — почему один mutex
  закрывает гонку «паника vs таймаут».
- `router.go`: комментарий к `newRouter` — это контракт порядка.
- `logger.WithAttrs` создаёт новый слайс, а не `append` к родительскому:
  иначе два дочерних контекста писали бы в общий backing array.

## Что можно было сделать иначе

- Инвариант `HANDLER < WRITE` строгий, без запаса. Между ними запись 503;
  при 14.99s/15s её может не хватить. Можно требовать зазор (например, 1s).
- Access-лог для `/healthz`/`/readyz` пишется на info: при частых пробах это
  шум. Можно понижать до debug по шаблону маршрута.
- Timeout не поддерживает `Flush`/`Hijack`. Когда появится стриминг, либо
  отдельная ветка роутера, либо Timeout, который пропускает Flush-запросы.
