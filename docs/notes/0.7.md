# 0.7 — вход в фазу 1

Цель этапа: закрыть архитектурные решения и платформенные примитивы, на
которые опирается первый бизнес-модуль (IAM), чтобы его код не принимал их
неявно. Бизнес-логики нет: ни таблиц `iam.*`, ни регистрации, ни сессий.

## Стадия A — ADR 0011–0016

Шесть ADR предложены, прошли ревью владельца и приняты с правками
(`c232d89`). ADR-0009 заменён 0015.

Что изменило ревью:

| Пункт | Было в предложении | Стало |
|---|---|---|
| Классы таблиц (0011) | обычные `tenant`-таблицы видны пациенту | строгий вариант: `tenant` — только staff/system; новые классы `tenant-public` и `patient-registry` |
| Путь пациента (0011) | разрешение карточки под `system` | `PatientResolve(userID)` и RESTRICTIVE-политика на карточках: `system` в пути пациента нет |
| Лимит по IP (0016) | на все запросы | только для анонимных; аутентифицированные — по пользователю (CGNAT) |
| Транзакция в ctx (0012) | — | защита от параллельного использования в рантайме |
| Записи вне транзакции (0012/0014/0016) | — | `ErrInsideTx` |
| Аудит (0014) | `now()`, `=` в `WITH CHECK`, утверждение «субъект не подделать» | `clock_timestamp()`, `IS NOT DISTINCT FROM`, утверждение исправлено, добавлен `audit.Do` |
| Ячейки (0011) | — | явное ограничение «одна ячейка на пользователя» |

## Ключевые решения и почему

**Scope вместо tenant в контексте (0.7.1).**
- `WithinTx` выставляет **все четыре** параметра (`tenant_id`, `actor_kind`,
  `actor_id`, `patient_id`) в каждой транзакции, пустая строка — «не задано».
  Даже без `SET LOCAL` значение прошлой транзакции не пережило бы
  следующую: она перезаписывает все четыре. `SET LOCAL` здесь — второй
  рубеж.
- Вложенный вызов с тем же scope — `SAVEPOINT` на том же соединении.
  Интеграционный тест при `MaxConns=1` сверяет `txid` и `pg_backend_pid`
  снаружи и внутри.
- `DBTX`-обёртка держит флаг занятости на время запроса, а для `Query` — до
  `Rows.Close`. Одновременное использование транзакции даёт
  `ErrTxConcurrentUse`, а не порчу протокола.

**Шаблоны политик (0.7.2).**
- RESTRICTIVE — инварианты изоляции, PERMISSIVE — разрешения.
- Тест схемы сверяет **точный набор** политик (имя, тип, команда) у каждой
  таблицы и `class=` в комментарии.
- Мутация M2 ниже показала границу теста схемы: он не видит выражений
  внутри политик. Подмену выражения ловят только поведенческие тесты
  классов. Нужны оба уровня.
- Функции `platform.current_*()` закрывают ловушку «пустая строка вместо
  NULL» в одном месте; в политиках они обёрнуты в `(SELECT …)` ради InitPlan.

**Тест архитектуры (0.7.3).** Только stdlib: `go/parser` для импортов, AST
для `time.Now`. Фикстурам в `testdata` не нужно компилироваться, поэтому
на каждое правило есть своя фикстура-нарушитель. Проверяются:
- границы модулей;
- роли пакетов;
- ацикличность графа модулей;
- `time.Now` / `Since` / `Until` в `domain` и `app`, в том числе под
  алиасом.

**Кодогенерация (0.7.4).**
- Инструменты в `backend/tools/go.mod`; основной `go.mod` не тронут.
- sqlc собирается без cgo.
- Ошибки параметров сгенерированного кода превращаются в RFC 9457 по имени
  параметра: `ParamName` читается рефлексией, потому что у каждого
  сгенерированного пакета свои типы ошибок.
- runtime oapi-codegen пока не нужен: у health-эндпоинтов нет параметров.
  Он появится с первым параметризованным эндпоинтом модуля.

**Аудит (0.7.5).**
- Клинику и субъект подставляет сама БД в `INSERT`
  (`platform.current_*()`), а не Go-код. `WITH CHECK` дублирует это для SQL
  в обход `Recorder`.
- `Do` — основной путь: scope действия и события отказа совпадают по
  построению.

**CORS и CSRF (0.7.6).**
- CORS внутри Recover, CrossOrigin сразу после него.
- CrossOrigin — stdlib `http.CrossOriginProtection`, своего кода почти нет.
- Preflight в access-логе помечается `route=preflight`.

**Rate limit (0.7.7).**
- Ключ — HMAC с длиной частей перед значением: `("ab","c")` ≠ `("a","bc")`.
- Memory ограничивает число ключей и при переполнении пропускает запрос без
  учёта (fail open).
- Postgres пишет счётчик своей транзакцией (`ErrInsideTx` внутри чужой).
- Один набор тестов `ratelimittest.Run` для обеих реализаций.
- IP кладётся в контекст, в логи не попадает.

## Что не проверено

- **CI на GitHub.** Workflow с новым job `generate` запускался только
  локально, теми же командами.
- **Dependabot.** Конфиг не проверен GitHub. Экосистему `docker-compose` я
  указал по памяти: если GitHub её не примет, он покажет ошибку в
  Insights → Dependency graph, и этот блок надо убрать.
- **`Postgres`-лимитер и `audit.Recorder` не подключены в `internal/app`:**
  ими пока никто не пользуется. Фоновую очистку окон
  (`DeleteExpired`) запустит IAM вместе с первым точным лимитом.
- **Маппинг `format: uuid` в oapi-codegen на `id.ID`.** Сейчас в
  спецификации нет uuid-параметров; с первым модулем — `x-go-type` или
  конвертация в адаптере.

## Критерий «новый модуль без правок платформы»

Модуль IAM начинается с файлов в `internal/modules/iam/`:
- `doc.go` каждого пакета описывает назначение;
- тег `iam` в `openapi.yaml` + конфиг `oapi-codegen.yaml` в
  `adapters/http/api/`;
- запросы в `adapters/postgres/queries/` + блок в `sqlc.yaml`;
- миграция `0005_iam_*.sql` с `class=` и шаблоном политик;
- wiring — строка в `registerRoutes` и конструктор в `app.New`.

Тест архитектуры и тест схемы проверят, что модуль не вышел за шаблон.

## Что можно было сделать иначе

- Тест схемы сверяет имена и типы политик, но не их выражения (см. M2).
  Можно сравнивать нормализованные `pg_get_expr(polqual)` с эталоном
  класса — хрупко при смене имён столбцов, поэтому оставлено поведенческим
  тестам.
- `ParamErrorHandler` использует рефлексию. Альтернатива — свой шаблон
  oapi-codegen с общим интерфейсом ошибок; хрупко при обновлении
  инструмента.
- Лимитер в памяти — fixed window. GCRA дал бы плавность без всплеска на
  стыке окон.
- Шаг разрешения карточки и работа с ней — две транзакции на запрос
  кабинета пациента. Можно кешировать разрешение на время сессии.
- Не сделано по ADR-0014: партиционирование `audit.events`, hash-цепочка,
  экспорт во внешнее хранилище, роль чтения.
