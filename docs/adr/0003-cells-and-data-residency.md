# 0003. Ячейки и резидентность данных

- Статус: Принято
- Дата: 2026-09-27

## Контекст

Клиники находятся в разных юрисдикциях. Закон РК о персональных данных
требует хранить персональные данные граждан на территории РК; GDPR
ограничивает передачу данных за пределы ЕЭЗ; у отдельных клиентов могут
быть договорные требования к региону. Переделать глобальную БД в
региональные после запуска — миграция медицинских данных между
юрисдикциями, то есть самое дорогое и рискованное изменение из возможных.
Поэтому решение принимается с первого дня, даже при одной ячейке.

## Решение

- **Ячейка (cell)** — полный стек: API, Postgres, объектное хранилище,
  очереди, развёрнутый в одном регионе. Ячейки не делят хранилища.
- **Tenant (клиника) закреплён ровно за одной ячейкой.** PHI tenant'а
  никогда не покидает регион ячейки.
- **Глобальный слой** хранит только маршрутизацию tenant → ячейка и данные
  без PHI. Он не проксирует медицинские данные между регионами.
- Следствия для кода уже в фазе 0:
  - процесс знает только свою ячейку: вся конфигурация — из окружения, нет
    глобальных синглтонов и «общих» подключений к чужим регионам;
  - tenant передаётся явно (`shared/tenant` в контексте), а не выводится
    из глобального состояния;
  - идентификаторы — UUID (в PG18 — `uuidv7()`), без последовательностей,
    уникальных только в пределах одной БД: tenant можно перенести между
    ячейками без перенумерации.

## Альтернативы

- **Одна глобальная БД с колонкой region.** Проще в эксплуатации, но данные
  физически в одной юрисдикции; изоляция по региону — фильтр в запросе,
  а не граница инфраструктуры.
- **БД на каждого tenant'а.** Сильная изоляция, но тысячи баз: миграции,
  пулы соединений и мониторинг масштабируются плохо. Изоляцию внутри ячейки
  даёт RLS (см. [0004](0004-medical-record-ownership-and-rls.md)).

## Последствия

- Каждая ячейка разворачивается и мигрируется независимо: миграции и
  конфигурация не должны предполагать «одну систему».
- Межрегиональная аналитика — только через обезличенный экспорт.
- Перенос tenant'а между ячейками — отдельная процедура (фаза позже), но
  модель данных её не запрещает.
- Спроектировано по контролям: GDPR ст. 44–46 (передача данных в третьи
  страны), ст. 25 (защита данных by design); ISO/IEC 27701 (обработка PII);
  требования законодательства РК о локализации персональных данных.
