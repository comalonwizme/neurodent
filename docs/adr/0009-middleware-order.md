# 0009. Порядок HTTP middleware

- Статус: Заменён [0015](0015-cors-csrf-and-middleware-order.md)
- Дата: 2026-09-27

## Контекст

Сквозные функции HTTP-слоя (идентификатор запроса, access-лог,
заголовки безопасности, перехват паник, лимит тела, таймаут) зависят друг
от друга: от порядка зависит, будет ли у ответа на панику `request_id`,
увидит ли access-лог итоговый статус 503, получат ли 413 и 500
security-заголовки.

## Решение

Снаружи внутрь (`internal/app/router.go`, `newRouter`):

```
RequestID → AccessLog → SecurityHeaders → Recover → BodyLimit → Timeout → routeProblems(mux)
```

| Слой | Почему здесь |
|---|---|
| RequestID | id нужен всем ниже: логам паник, access-логу, телам ошибок |
| AccessLog | снаружи Recover и Timeout — видит итоговый статус и полную длительность |
| SecurityHeaders | снаружи всех, кто сам пишет ответ (Recover, BodyLimit, Timeout) |
| Recover | снаружи Timeout — Timeout переносит панику из goroutine хендлера |
| BodyLimit | до Timeout — 413 по Content-Length без запуска goroutine |
| Timeout | ближе всех к хендлеру — бюджет тратится только на хендлер |
| routeProblems | 404/405 роутера в формате RFC 9457 |

Сопутствующие решения:

- **Свой Timeout вместо `http.TimeoutHandler`**: stdlib отдаёт `text/plain`
  без `request_id`. Ответ буферизуется, клиент получает либо ответ
  хендлера, либо 503 — не смесь. Цена: нет потоковой отдачи; стриминговые
  эндпоинты (AI-ассистент) монтируются мимо Timeout.
- **Access-лог без PII**: метод, шаблон маршрута (не путь), статус,
  длительность, размер, `request_id`. Не пишутся путь, query, IP,
  User-Agent.
- **Входящий `X-Request-ID`** принимается при длине 8–64 и алфавите
  `[A-Za-z0-9._-]`, иначе генерируется свой.

## Альтернативы

- **Recover самым внешним.** Ловит панику и в самих middleware, но ответ
  на панику не получает `request_id` и security-заголовков, а access-лог
  не видит 500. Внешние слои — простые обёртки без логики, паниковать им
  нечем.
- **Timeout снаружи BodyLimit.** Чтение большого тела расходует бюджет
  хендлера, а 413 по Content-Length запускает лишнюю goroutine.

## Последствия

- Порядок проверяется тестом по наблюдаемым следствиям
  (`TestRouter_ErrorResponsesAreUniform`): ошибка из любого слоя даёт
  problem-ответ с `request_id` и заголовками безопасности и попадает в
  access-лог с итоговым статусом. Перестановка слоёв ломает тест
  (проверено мутациями).
- Новый middleware добавляется с обоснованием места в этой таблице.
- Спроектировано по контролям: HIPAA 45 CFR §164.312(b) (аудит — без PHI в
  журналах); ISO/IEC 27001:2022 A.8.15 (журналирование), A.8.28.
