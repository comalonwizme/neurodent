# Architecture Decision Records

ADR фиксирует значимое решение: контекст, само решение, рассмотренные
альтернативы и последствия. ADR не редактируют задним числом: если решение
меняется, пишут новый ADR со статусом «Заменяет NNNN», а старому ставят
«Заменён NNNN».

О соответствии требованиям пишем только «спроектировано по контролям X».
Формулировки «соответствует» и «сертифицировано» не используем: соответствие
подтверждает аудит, а не код.

## Шаблон

```markdown
# NNNN. Название

- Статус: Предложено | Принято | Заменён NNNN
- Дата: ГГГГ-ММ-ДД

## Контекст
Какую проблему решаем, какие силы и ограничения действуют.

## Решение
Что решили, конкретно.

## Альтернативы
Что рассматривали и почему отказались.

## Последствия
Что становится проще, что сложнее, какие обязательства мы на себя берём.
```
